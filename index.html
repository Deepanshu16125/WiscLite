Teaching-scale engine: single-threaded, size-tiered (not leveled) compaction, stop-the-world value-log GC, and scans slower than the baseline. Same idea as Badger and TiKV's Titan, built from scratch.

Use it

The whole API, in eight lines

A CLI over a library crate. serve runs this site plus a JSON API on localhost.

$ wisclite put hello world
$ wisclite get hello           # world
$ wisclite del hello           # tombstone
$ wisclite scan a z            # range [a, z)
$ wisclite gc                  # reclaim the vlog
$ wisclite stats
$ wisclite bench               # → bench.json
$ wisclite serve --port 7878   # site + JSON API
The idea

Same write path, one decision apart

LSM trees stay fast by sorting data in the background (compaction). That sorting copies every value again and again. WiscKey moves the values out of the tree, so compaction only shuffles small pointers.

Classic LSM (baseline)

  1. Log key + 1 KB value to the WALfor crash recovery
  2. Insert key + value into the memtablesorted, in memory
  3. Flush the memtable to an sstablethe value is written again
  4. Compact sstables as they pile upthe value is rewritten once per merge

WiscKey (WiscLite)

  1. Append the 1 KB value to the value logwritten once, never moved by compaction
  2. Log key + 21-byte pointer to the WAL
  3. Insert key → pointer into the memtable
  4. Flush and compact pointers onlythe tree is ~16× smaller, so merges are cheap

Honest scope

Built vs not yet

Built and tested

  • WAL with CRC32, torn-write-safe replay
  • Append-only value log with checksums
  • BTreeMap memtable, sorted sstables with binary-search index
  • Bloom filter per sstable (measured FPR ≈ 0.7–0.8%)
  • Size-tiered compaction that drops tombstones at the oldest tier
  • Ordered range scans across memtable and tables
  • Value-log GC with reclaimed-bytes report
  • Atomic MANIFEST for crash-safe flush, compaction and GC
  • Inline-value baseline mode, bench, local HTTP server

Not yet

  • Leveled compaction (deeper trees widen the gap)
  • Incremental head/tail GC from the paper (mine is stop-the-world)
  • Parallel vlog prefetch for scans (WiscKey scans are slower today)
  • Block index and block cache (all keys indexed in RAM)
  • Concurrency, snapshots, vlog-as-WAL
  • WASM build of the real engine for this page
